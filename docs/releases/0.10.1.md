# 0.10.1 preparation and upgrade

Prepared 2026-10-08. This core patch repairs bound-product integration generation. No tag is
created by this work; the PO publishes from reviewed main after Framework CI and Test Copier
Template pass, including the slow lane. Package publication and orchestrator pin changes are
separate operations.

## Container generation

The generated integration service runs `python -m framework.generate` before its unchanged
`pytest -q tests/integration`. A default binding requires installed backend and tg_bot
environments inside the product root; parser admission also reads the bot's installed library
metadata. The checkout bind mount previously exposed host-built virtualenvs at these paths.
Their Python executables can point outside the container, even though the integration process
itself uses the backend image's working `/app` interpreter.

The backend dev image now seeds root tooling and backend environments under `/workspace`, and
for backend,tg_bot also builds the bot's frozen runtime dependencies, copying local library
wheels before sync. Integration Compose masks the mounted host environments with anonymous
volumes initialized from those image directories. Binding validation still requires owned
product environments and checks actual installed distributions and library signatures. The
integration command, Make target, tests, database and Redis contracts are unchanged; no test is
skipped. The normal runtime image retains only its backend dependencies.

## Published-package regression

The slow Copier lane generates backend,tg_bot with exact candidate tooling, installs through
the default live catalog and published package tags, binds the installed default, regenerates,
and executes the generated product's own `make test-integration`. The two cases cover reminders
0.5.0 plus textparse 0.1.0, and tg-channels 0.1.0. The test pins the product Makefile, integration
Compose and test bytes before installation and checks them again before and after execution.
The `bound-product-integration-<run-id>` artifact retains each command's complete output,
exit status, candidate identity, component versions and integration contract hashes.

The channels case verifies the installed platform key/base URL declarations, service, scopes,
quota and declared endpoint. Only its disposable `.env` supplies
`PLATFORM_KEY=integration-only-inert-key` and
`PLATFORM_BASE_URL=https://platform.invalid/tg-reader`. No runtime fallback is added. Package
startup constructs its client without a request; the product tests exercise core health,
OpenAPI, migrations and Redis delivery, and never create channel subscriptions or call channel
actions. With no subscriptions the timer does not fetch posts. Thus the suite needs no real
platform and its inert endpoint cannot reach one.

Workers run permitted focused tests and the canonical non-slow broad wrapper locally; Docker
and the published-package integration cases run in CI. A worker-local receipt does not replace
the slow CI result or a dispatcher-owned gate receipt.

## Versions and existing products

The kit tag advances from 0.10.0 to 0.10.1 after PO publication. The facade remains 2.4.0,
package protocol 1 and tooling/application distribution 0.1.0. No package release or
`requires_core` change is needed.

After publication, run
`uvx copier update --defaults --trust --vcs-ref=0.10.1 --conflict=rej`, review conflicts,
then `make setup` and `make generate-from-spec`. Commit the updated template files, answers,
tooling lock and generated files, then run the product's checks and `make test-integration`
in its CI environment. Review the backend Dockerfile and integration Compose changes together.
Existing bindings and settings remain product-owned; platform values still require explicit
configuration. No stand run or live product update is part of this patch.
