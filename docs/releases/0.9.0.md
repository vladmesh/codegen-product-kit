# 0.9.0 preparation and upgrade

Prepared 2026-10-07 after 0.8.1. This minor core release adds generic platform environment
declarations and supersedes the untagged [0.8.2 xenon patch](0.8.2.md), already merged on main.
One tag carries both changes. This work creates no tag: after reviewed main and green required
Framework CI and Test Copier Template, including the slow lane, the separate PO release operation
checks availability and publishes annotated `0.9.0` at the reviewed merge. Published tags remain
immutable. Package publication, orchestrator resolution, contract-copy sync and pin movement
belong to separate operations.

## Package environment sources

An optional discriminated `environment[].source` in `package.yaml` declares `platform_key`
with a service name, explicit scopes and non-negative integer quota, or `platform_base_url`
with a service name and explicit HTTPS URL. Generation carries those exact fields into the
packages env fragment under the matching `source` instead of asking for a `user_secret`.
Keys are sensitive and endpoints are non-secret. Service names are validated strings, not an
enum; kit core contains no concrete platform service, endpoint, credential prefix or grant default.
See [Environment contract v1](../CONTRACTS.md#environment-contract-v1) for the declaration and
validation rules. The model stays self-contained for a later orchestrator copy sync.

Unspecified requirements retain the current product reuse and user-secret behavior. Repeated
requirements combine requiredness; explicit source data must agree across packages and with any
existing product declaration. Invalid service names, HTTP URLs, negative or non-integer quotas,
unknown fields/kinds and conflicting sources fail loudly before writing the packages fragment.

## Included xenon fix

The producer splits generated command/callback/timezone and relay logic into focused helpers
that pass the product's existing complexity limits. Commands, callbacks, retries, lease cleanup
and replies retain their behavior. The real bound-product regression reads and runs both ruff
steps and xenon from the generated Makefile after two byte-identical regenerations and drift
checks. No lint thresholds or exclusions change. The prior defect and detailed proof remain
documented in [the superseded patch notes](0.8.2.md).

## Evidence and CI boundary

The synthetic platform-probe YAML declares fictional `geo-lookup`, scope `geo-lookup:read`, quota
`{lookups_per_day: 100}` and `https://platform.example.test/geo-lookup`. A local offline tagged
catalog test builds a real wheel, runs `kit add`, resolves its installed manifest and generates
the fragment and canonical contract with exact data. Validation, cross-package/product conflicts,
determinism, sensitivity, old fallback and generated-runtime admission have focused tests. A
unit test asserts `git grep -niE 'tg[-_ ]?reader|tg[-_]sources' -- framework template` is empty and
also guards against the fictional service leaking into core. Schema equality is tested against
the committed JSON export.

Required Framework CI runs lint and unit/tooling checks. Test Copier Template retains the fast
matrix, slow generated-product/upgrade, typecheck, real Redis and container lanes. The native
released 0.7.1 upgrade now expects candidate core 2.3.0; its old baseline and published components
stay unchanged. Slow/network/container runs are CI-only under this task's control-host rule.
Local focused/broad evidence cannot establish their result or replace a dispatcher-owned
exact-SHA gate receipt. Publication waits for those CI results.

## Existing products

After the PO publishes 0.9.0, run
`uvx copier update --defaults --trust --vcs-ref=0.9.0 --conflict=rej`, review all conflicts,
then run `make setup` and `make generate-from-spec`. Commit the updated answers/tooling lock,
façade and regenerated bindings/relay. Existing product fragments stay product-owned. Installing
a package using platform sources emits a packages fragment; a conflicting product variable
must be reconciled explicitly before generation succeeds. No platform key is issued by kit
tooling and no live environment is changed by this release preparation.
