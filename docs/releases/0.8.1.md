# 0.8.1 preparation and upgrade

Prepared 2026-10-07. The released baseline is annotated `0.8.0` (object
`09df6747c8030540789f97f9862f455af3dbb541`, peeling to
`b5716efe6ae03c13e1762e372c63e6639843d122`). Read-only remote tag inspection found no `0.8.1`.
This patch fixes generated output that failed the generated product's own CI; it changes no
runtime behaviour and no contract. No card creates or pushes a tag: after reviewed main and
required CI pass, a separate PO release operation must recheck availability and publish an
annotated `0.8.1` at the reviewed main merge. If occupied, report the collision and choose a new
version through that operation. Never move or replace a published tag.

## Defect

A product generated from `0.8.0` with a non-empty binding (for example after
`kit bind reminders --default`) fails its own PR CI. The generated `ci.yml` runs
`make generate-from-spec`, then `git diff --exit-code -- shared/shared/generated/
services/*/src/generated/`, then `make lint`, whose first step is:

```
.venv/bin/ruff format --check --exclude '*.md,.venv/**,**/.venv/**,services/**/migrations/**' .
unformatted: File would be reformatted
  --> services/tg_bot/src/generated/bindings.py
```

The generator's `format_file` ran `ruff format` and then `ruff check --fix`. In `bindings.py`
the UP034 fix removes the extra parentheses `pformat` puts around the long JSON string inside
`json.loads(...)`, leaving a whitespace-only line and over-indented string lines that nothing
reformatted. `make lint` passes `--exclude` on the command line, which replaces `ruff.toml`'s
`**/generated/**` exclusion, so the format check covers generated files. A committed
`bindings.py` therefore could not satisfy both the drift check and the lint step: formatting it
by hand made the next regeneration differ.

## Fix

`BaseGenerator.format_file` runs `ruff format` once more after `ruff check --fix`. Every
generated Python file's final bytes are formatter output, so regeneration reproduces exactly
what `ruff format --check` accepts. The bindings template, the generated data and the product
lint contract are unchanged; generated trees remain format-checked by `make lint` and excluded
from `ruff check` by `ruff.toml`, as before. Files that were already stable are byte-identical.

The lint exclusions were deliberately left alone: excluding generated trees from the format
check would only hide the generator emitting unformatted code, and would change the product's
lint contract for every product rather than fix the producer.

## Evidence

`tests/copier/test_bindings.py::test_bound_product_generation_passes_its_own_drift_and_ruff_lint`
(non-slow copier layer) copies a real backend,tg_bot product bound to the actual reminders
default binding with the real textparse library, points the product root `.venv/bin/ruff` at the
kit's pinned ruff so the real formatter and fixer run, commits a regeneration, then twice runs
regeneration, the CI drift `git diff --exit-code` over the generated trees and the `ruff`
steps of the product Makefile's own `lint` recipe (read from the generated Makefile, not
copied). It requires both runs to produce byte-identical generated files. Without the fix it
fails with the `bindings.py` reformat diff above. The remaining `make lint` steps (xenon,
controller sync, package imports) are untouched by this change and keep their existing
generation-matrix coverage in CI.

| Kit core tag | `0.8.0` | `0.8.1` |

No package release is needed: `requires_core` ranges are unaffected and no package tag moves.

## Orchestrator and existing products

- The orchestrator moves its kit pin (`scheduler.service_template_ref`) from `0.8.0` to `0.8.1`
  after the PO operation publishes the tag.
- An existing product updates with
  `uvx copier update --defaults --trust --vcs-ref=0.8.1 --conflict=rej`, then `make setup` and
  `make generate-from-spec`; the regenerated `bindings.py` is formatter-stable and is committed
  with the update.
