# 0.10.0 preparation and upgrade

Prepared 2026-10-07 after 0.9.0. This core minor adds finite bilingual Telegram binding v2
beside the pinned v1 grammar. This work creates no tag. Publication belongs to the separate
release operation after reviewed main and green Framework CI and Test Copier Template,
including the slow lane. Package releases and live product changes remain separate operations.

## Binding v2

V2 supports plain text creation with declared action error replies, lists with an optional
equality filter and per-item buttons, a no-argument result-list show, and event delivery.
Every binding text has exactly `ru` and `en` entries. One product setting chooses the language;
commands, callbacks and events read it through `/settings/get`. Missing or invalid configuration
produces an explicit bilingual setup reply. There is no default language, per-user language,
translation, parser, `/lang` command or platform client. A relay setup reply retains the original
event for retry after configuration recovery. Date display requires an explicit product
timezone and uses an RU or EN month table. See [Finite binding v2](../CONTRACTS.md#finite-binding-v2).

Bind declares `{type: string, enum: [ru, en]}` in the bot manifest, preserving product ownership
and unrelated settings. It declares the optional timezone only when supplied. The operator
writes values separately through the existing product-scoped settings contract. Regeneration
validates the complete binding set before writing output. V1 and v2 can coexist in one product;
commands and events remain unique across that set.

## Versions and compatibility

| Item | Before | After |
|---|---|---|
| Kit core tag | `0.9.0` | `0.10.0` (prepared, no tag) |
| Generated façade `CORE_VERSION` | `2.3.0` | `2.4.0` |
| Package protocol | `1` | `1` |
| Binding grammar | `1` | `1` and `2` |
| Tooling/application distribution | `0.1.0` | `0.1.0` |
| Minimum Copier | `9.0.0` | `9.0.0` |

Packages shipping a v2 default or the additive `actions[].errors` metadata must declare
`requires_core: ">=2.4,<3"`. V2 admission independently refuses an older product façade.
Error codes are unique declared identifiers; only an HTTP 4xx `detail.code` from that declaration
can select a binding's localized `on_error` reply. Unknown codes and other backend failures
use the localized generic failure reply, never backend error text.

Existing compatible package ranges remain valid. Reminders 0.5.0 (`>=2.2,<3`), its default
binding, and textparse 0.1.0 remain unchanged. V1 validators retain their exact grammar;
v1-only generated bindings and relay match pinned pre-v2 bytes. V1 retains its English parser,
three presets and mandatory timezone. No package is migrated by this release.

## Validation and evidence boundary

The inert synthetic binding-notes fixture exercises all v2 commands, remove callbacks, localized
errors, no-results replies, product setting failures, date formatting and event delivery in RU
and EN inside a Copier product with reminders also bound. It uses fake HTTP, Telegram and Redis
state; it does not claim real Redis or package integration. Admission tests cover missing/extra
locales, unknown keys/actions/events/fields, incompatible schemas, branch sources, duplicate
commands/labels and setting ownership. Pinned v1 files assert emission compatibility.

The bound-product regression runs the generated Makefile's ruff and xenon commands and checks
two byte-identical regenerations for v1, v2-only and mixed v1/v2 products. The slow CI regression
runs the v2 product's `make typecheck`, checking each service's output as well as the exit code.
Existing real Redis, container, published-component and released-core upgrade proofs retain their
CI routes. The released 0.7.1 upgrade and façade activation tests now expect candidate 2.4.0;
the immutable baseline and package minimum 2.3 remain unchanged.

Workers run only the permitted focused subsets and canonical broad wrapper. Local receipts
cannot establish slow CI results or replace a dispatcher-owned exact-SHA gate receipt.

## Existing products

After publication, run `uvx copier update --defaults --trust --vcs-ref=0.10.0 --conflict=rej`,
review conflicts, then run `make setup` and `make generate-from-spec`. Commit answers, tooling
lock, façade and generated files. Existing v1 bindings remain product-owned and byte-stable.
A v2 product additionally generates `bindings_v1.py` as the shared v1 runtime companion;
v1-only generation removes that companion and uses the original two-file output.
Install and bind a released v2-capable package only after this upgrade. Set its declared
product language explicitly before using commands or delivering events.
