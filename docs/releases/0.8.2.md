# 0.8.2 preparation (superseded before publication)

Prepared 2026-10-07 as a core patch release after 0.8.1, then superseded while still untagged by
[0.9.0 preparation](0.9.0.md). The defect and fix below are retained as evidence. The PO releases
one annotated `0.9.0` tag carrying this xenon fix and the generic platform environment declaration;
do not publish the formerly proposed `0.8.2`. Never move or replace a published tag.

## Defect

The sprint:1482 precondition run 37626697287 installed kit 0.8.1, reminders 0.5.0 and textparse
0.1.0 into a backend,tg_bot product. After binding and generation, the product PR failed
`make lint`. The 0.8.1 format fix worked; ruff passed. Xenon failed on generated code:

- `binding_relay.py`: `deliver` ranked C, module B.
- `bindings.py`: `ChannelBindings`, `timezone` and `callback` ranked C, `command` D, module B.

The generated Makefile requires `--max-absolute B --max-modules A --max-average A`. The
previous bound-product regression ran only its ruff steps, leaving the complexity failure
uncovered by that proof.

## Fix

The producer templates split command execution into parsed-create and list helpers, validate
settings response metadata separately from IANA timezone values, and separate callback
selection and ownership checks from execution. Callback choices are still consumed before the
first await. The relay separates envelope validation, timed sending, terminal Telegram refusal
and claim completion. Completed claims retain seven-day dedupe; transient failures and
cancellation release only the current lease. Parser invocation, reply rendering, presets and
action requests retain their behavior.

The generated product's lint recipe, exclusions and thresholds stay unchanged. The kit's dev
dependencies now include xenon so the regression uses a real executable under the lock. No
runtime dependency or generated façade change is needed.

## Evidence

`tests/copier/test_bindings.py::test_bound_product_generation_passes_its_own_drift_and_lint`
uses a real backend,tg_bot Copier product with actual reminders and textparse sources installed
and the installed reminders default binding. It reads both ruff steps and the xenon command
from that product's Makefile, including its original flags and exclusions. Each of two
regenerations must pass the generated-tree Git drift check and those three lint steps, with
byte-identical output. Extending the test before changing the templates reproduced all seven
xenon failures above.

The existing generated-handler and relay scenarios retain their assertions. Additional
refusals cover invalid settings metadata and timezone prefixes, invalid envelope versions,
terminal versus retryable Telegram BadRequest responses and cancellation lease cleanup.
The non-slow Copier matrix runs in required Test Copier Template CI; Framework CI retains
its lint/unit/tooling checks. Slow generation typechecks, real Redis and container/upgrade
proofs remain CI-only. Local focused and broad evidence does not replace those required CI
results or a dispatcher-owned exact-SHA gate receipt.
